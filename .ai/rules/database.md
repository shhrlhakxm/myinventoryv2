# Database

## Design inventory data for integrity and auditability
Explain tables, relationships, keys, indexes, constraints, normalization, and database-level integrity when relevant. Model real inventory events such as receiving, usage, adjustments, damage, duplicates, concurrent updates, and audit history. Never assume writes only arrive through the UI; use transactions, constraints, locking, or other safeguards when the business rule requires them.
